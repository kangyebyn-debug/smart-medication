## 1. 시스템 구성 개요

```
[React 19 SPA (Vercel)]
        │
        ▼
[FastAPI 백엔드 (Render)]
        │
        ├─▶ ① 공공 API (실시간 조회, 기존 유지)
        │     - 식약처 DUR API (XML)
        │     - e약은요 API (JSON)
        │     - 식약처 의약품 제품 허가정보 API (JSON, 상세정보 보완)
        │
        ├─▶ ② Supabase (관계형 DB + Auth + 파일 스토리지)
        │     - 계정/인증, 나의 약, 복약 질문 채팅 이력
        │     - 처방전에서 추출한 "마스킹된 구조화 데이터"만 저장
        │
        └─▶ ③ Pinecone (벡터 DB, RAG 전용)
              - 전체 의약품 설명 텍스트 임베딩
              - 복약 질문 AI 탭의 전체 약 데이터베이스 자연어 검색(범위 B)
```

DB는 **두 개로 분리**한다: 일반 구조화 데이터는 Supabase, RAG용 대량 벡터 데이터는 Pinecone. 분리 이유와 상세 스키마는 `03_DB_설계서.md` 참고.

## 2. 보안·개인정보 설계

### 2-1. 인증

- 비밀번호 해싱·세션 관리를 직접 구현하지 않고 **Supabase Auth에 위임**한다. (암복호화 구현 경험이 없다는 리스크를 줄이는 핵심 결정)

### 2-2. 처방전 처리 파이프라인 — 화이트리스트 방식

민감정보(주민등록번호, 환자번호/등록번호, 의사명, 병원명 등)를 "가려서 저장"하는 블랙리스트 방식 대신, **필요한 정보만 뽑고 나머지는 저장하지 않는** 화이트리스트 방식을 채택한다.

```
사용자가 처방전 사진 업로드
      │
      ▼
서버 메모리에서 OCR 수행 (디스크/DB에 원본 이미지 저장 안 함)
      │
      ▼
구조화 필드만 추출: 약품명 / 용량 / 복용 횟수 / 식전·식후 여부
      │
      ▼
원본 이미지 + OCR 원문 텍스트 즉시 폐기
      │
      ▼
추출된 구조화 필드만 Supabase `prescription_extracts`에 저장 (스키마는 03 문서 참고)
```

- 이렇게 하면 환자번호 형식이 병원마다 달라 정규식으로 못 잡아내는 문제, 의사명·병원명을 일일이 식별해야 하는 문제 자체가 사라짐 (애초에 추출 대상이 아니므로 저장되지 않음).
- **이중 안전장치**: 혹시 모를 로그/디버그 출력에 원문이 찍히는 것을 막기 위해, 주민등록번호 패턴(예: `\d{6}-?[1-4]\d{6}`)을 정규식으로 탐지해 로그 레벨에서 강제 마스킹 처리.

### 2-3. 로그아웃 상태 허용 라우트

- `GET /drugs/search`, `GET /drugs/image`, `GET /drugs/warnings`(한 약품의 금기 조회), `GET /drugs/check`(두 약품의 병용금기 비교)는 인증 미들웨어를 거치지 않는 공개 라우트로 유지.
- 계정 연동이 필요한 기능(나의 약, 복약 질문 AI 탭, 처방전 업로드)만 인증 필요.

## 3. 심평원 투약이력 연동 — 보류 섹션

- 확인된 사실: 건강정보 고속도로(마이헬스웨이) 공식 포털의 개인/기관 안내 페이지에는 데이터 제공 대상으로 "병·의원 등 의료서비스 제공자, 보건의료 관련 기업, 연구기관"만 언급되고, 개인 개발자 등록 경로나 비용·보안인증 요건은 명시돼 있지 않음.
- 판단: 비영리 개인 프로젝트로서 단기간에 연동 가능한지 **확인되지 않음** → 장기 과제로 분류, 가까운 로드맵에서 제외.
- 재검토 조건: 포털에 개인 등록 메뉴가 생기거나, 문의처(1666-7598)를 통해 개인 참여 가능 여부가 확인될 경우.
