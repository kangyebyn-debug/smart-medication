- 작성일: 2026.11.17
- 작성자: 강예빈
- 성격: **비영리 개인 사이드 프로젝트** (수익화는 목표가 아님). AI를 활용해 기획→설계→개발→배포 전 과정을 끝까지 완성하고, AI 핸들링 능력을 보여주는 것이 1차 목표.

## 2. 메인 기능 재정의

기존(v1)에서는 "약품 검색 / 병용금기 확인"이 전부였다면, v2에서는 아래를 **메인 기능**으로 재정의한다.

### 2-1. 복약 질문 AI 탭 (★ 메인 기능)
- 처방전을 촬영해서 올리거나, 복용 중인 약 조합을 직접 세팅
- "이거 식후에 먹는 거야?", "이 약들이랑 술 마셔도 돼?" 같은 **구어체 질문**을 AI가 해석해서 답변
- 범위: 사용자가 등록한 약뿐 아니라, **전체 의약품 데이터베이스를 대상으로 한 자연어 검색/질의**까지 포함 (범위 B로 확정)
- RAG(검색증강생성) 구조로 구현 — 전체 의약품 설명 텍스트를 임베딩해 벡터 검색 후 LLM이 답변 생성

### 2-2. 약 상세정보 보강
- 기존: 병용금기·임부금기·노인주의·연령금기 탭만 제공
- 추가: 1일 복용 횟수, 식전/식후 여부 등 실제 복약에 필요한 정보 보강

### 2-3. 음식-약물 상호작용 (원래 프로젝트 시작 당시 목표)
- 자몽, 우유, 알코올 등 음식과 약물의 상호작용 경고
- v1 문서에서는 "향후 계획"으로만 적혀 있었으나, 애초 기획 의도였던 항목이므로 로드맵 상 우선순위를 앞으로 당김

## 3. 기능 범위 — 로그인 여부 기준

| 기능 | 로그인 필요 여부 | 비고 |
|---|---|---|
| 약품 검색 | **불필요** | 로그아웃 상태에서도 항상 사용 가능해야 함 |
| 병용금기 확인 | **불필요** | 〃 |
| 나의 약 (저장) | 필요 | 계정 단위로 여러 기기에서 동기화 (기존 localStorage 방식에서 전환) |
| 복약 질문 AI 탭 | 필요 | 질문 이력을 계정에 귀속해 어느 기기에서 로그인해도 확인 가능 |
| 처방전 업로드 | 필요 | 민감정보 처리가 동반되므로 인증된 사용자만 |

## 4. 타겟 사용자

- (기존) 처방약과 일반의약품을 함께 복용하려는 일반 소비자 — 의료 지식 없이도 즉시 확인 가능해야 한다는 전제
- (확장) 여러 약을 한 번에 처방받아 "이걸 어떻게 먹어야 하는지" 헷갈리는 사용자 — 구어체 질문 해석 기능으로 대응

## 5. 비범위 (Out of Scope, 현 단계)

- **수익화** — 이 프로젝트의 목표가 아님
- **건강보험심사평가원(HIRA) 투약이력 공식 연동** — 공공 "건강정보 고속도로(마이헬스웨이)" API 확인 결과, 제공/활용 주체가 병·의원 등 **기관 단위**로 한정되는 것으로 보이며 개인 등록 경로가 공개 페이지에 없음. 개인 무료 프로젝트로 단기간에 구현 가능한지 확인되지 않아 **장기 과제로 보류**한다.

## 6. 로드맵 개요 (상세는 설계서·로드맵 문서에서 다룸)

| Phase | 내용 |
|---|---|
| Phase 1 | 약 상세정보 보강 |
| Phase 2 | 계정/DB 기반 전환 (Supabase Auth + 나의 약 동기화) |
| Phase 3 | 복약 질문 AI 탭 — 등록된 약 기준 (소규모, RAG 없이 프롬프트 직접 주입) |
| Phase 4 | 복약 질문 AI 탭 — 전체 의약품 대상 확장 (RAG, 벡터DB 도입) |
| Phase 5 | 처방전 OCR + 마스킹 파이프라인 |
| Phase 6 | 음식-약물 상호작용 |
| Phase 7 | 크로스플랫폼(iOS/Android) 전환 |
| 장기 과제 | 심평원 투약이력 연동 (기관 등록 가능 여부 재확인 후 재검토) |
